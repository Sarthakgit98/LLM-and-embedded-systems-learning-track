01The Big Picture

Everything in this course is one story told from seven angles:

  1. Vectors & spans — the raw material (arrows, lines, planes).
  2. Matrices as transformations — what matrices do: they move the grid.
  3. Rank & column space — which directions survive the transformation.
  4. Determinants — how much area/volume the transformation scales.
  5. Dot products & duality — measuring, projecting, and the hidden arrows inside 1×2 matrices.
  6. Eigenvalues & change of basis — the directions that don't tilt, and the rulers we choose to describe vectors.
  7. SVD — the grand finale: every transformation is rotate → stretch → rotate.
The master intuition: a matrix's columns are where the basis vectors land. Nearly everything else — rank, column space, determinants, SVD — is just asking "what happens to the grid?"

02Spans, Bases & Subspaces

Span

The span of a set of vectors = all vectors you can reach by scaling and adding them (all linear combinations). Visualize: the largest flat thing you can sweep out from the origin using those vectors' directions.

  • 1 independent vector → a line (1D)
  • 2 independent vectors → a plane (2D)
  • k independent vectors → a k-dimensional subspace
Span of two vectors in a plane
Two independent vectors (blue, green) + a reachable combination (red) — the shaded region they sweep out is the span.

Basis

A basis = a linearly independent spanning set. Your understanding, refined:

"Bare minimum" is right — but there's no unique minimum. Infinitely many bases exist (rotate {(1,0),(0,1)} and you get another one). What is unique is the number of vectors — the dimension. The real reason bases matter: every vector has exactly one representation in a given basis — a unique "address." Too few vectors → no address; too many → many addresses (ambiguity).

The "remove redundant vectors" algorithm works, with one nuance: dependence doesn't partition cleanly. The correct rule is iterative — remove any vector expressible via the rest, repeat. Which basis you end with depends on removal order; the size never does.

Subspaces — "whole space" is relative

In ℝ³ (ambient space): 1 vector spans a line, 2 independent vectors span a plane — a proper subspace, a 2D sheet floating inside the 3D room. Only 3 independent vectors span the whole space.

  • "Whole space" ≠ infinite dimensions. It means "fills all n dimensions of the ambient space."
  • Infinite-dimensional spaces exist, but every finite set of vectors spans a finite-dimensional subspace — not the case to worry about here.
  • Every subspace is itself a complete vector space; "subspace" just means "viewed from inside a bigger space."

03Matrices as Transformations

The one rule that unlocks everything

columns = images of i-hat, j-hat, k-hat

A matrix is fully described by where it sends the basis vectors. The i-th column is the landing spot of the i-th basis vector. This is why every matrix property reduces to "what happens to the grid."

Visualizing a shear with CSS

The shear [[1,1],[0,1]] — click to apply

i-hat stays put (first column (1,0)); j-hat tips right (second column (1,1)). The grid deforms; a vector at address (2,3) stays at address (2,3) on the new grid — which is the physical point (5,3).

Composition order (AB vs BA)

AB means "apply B first, then A" — read right-to-left: (AB)v = A(Bv). AB ≠ BA in general — socks before shoes vs shoes before socks. But determinants commute: det(AB) = det(BA), because scalars commute even when matrices don't.

A programmer's hook: a linear system Ax = b reads row by row — each row is one equation (one constraint). The columns describe how each variable behaves across all equations.

04Rank & Column Space

Rank

Rank = number of linearly independent columns = the dimension of the output space = how many dimensions the transformation preserves.

  • Full rank (n×n): invertible, det ≠ 0, columns independent, every b solvable with a unique solution.
  • Rank < n: some dimension got squished. det = 0. The squish direction maps to zero (the kernel).
  • Rank-nullity theorem: rank + nullity = number of columns. What survives + what gets annihilated = input dimension.

Column space — everything the transformation can reach

Column space = span of the columns = set of ALL possible outputs. Because Av = v₁·col₁ + v₂·col₂ + …, every output is a combination of columns — so "span of columns" and "set of reachable outputs" are the same set.
Ax = b has a solution ⟺ b is in the column space of A

For a programmer: the column space is the range of the function f(v) = Av. The codomain is where outputs nominally live; the column space is which outputs actually occur.

Column space of A = [[1,3],[2,6]] — the line y = 2x (rank 1)
Green dots = reachable b's (on the line) — solvable. Red dots = off the line — no solution exists, no matter what x you try.

Its SVD: σ = (5, 0) — the zero singular value is the squished dimension made literal.

05Determinants

The core idea

det(M) = the factor by which M scales all areas (2D) / volumes (3D) — uniformly, for every shape. Not just the unit square — any shape gets scaled by exactly |det|. The sign encodes orientation flip (reflection = negative).

Why det(M1M2) = det(M1)·det(M2)

One sentence: area-scaling factors compose multiplicatively — scale by det(M2), then by det(M1), gives total det(M1)·det(M2).

The hidden assumption that makes it work: det(M1) scales every shape by the same factor regardless of what M2 produced. If M1 scaled different shapes differently, the product formula would break. That uniformity is the whole point of the determinant — it's why the product representation is valid.

det = 0 means a dimension died

When a matrix's columns are linearly dependent, the transformation squishes space onto a lower-dimensional flat — volume collapses to zero, det = 0.

D.3 spotting skill: B = [[0,1,2],[3,4,5],[6,7,8]] has columns (0,3,6), (1,4,7), (2,5,8) — collinear, each the previous + (1,1,1). Three basis vectors landing on one line can't enclose volume → det = 0, rank 2. Rows equally spaced too — any matrix with evenly-spaced rows/columns is rank-deficient in disguise. And det(AB) = det(A)·det(B) = 18·0 = 0: once squished, never un-squished.

06Dot Products

Two faces of the same coin

u·v = u₁v₁ + u₂v₂ = |u|·|v|·cos θ
  • Algebraic face: multiply coordinates, add. Easy to compute, zero intuition.
  • Geometric face: |u| × (projection of v onto u) — "how much of v points along u, scaled by u's length."

Where cos θ comes from

Rearrange the geometric definition: cos θ = (u·v)/(|u|·|v|) — divide the dot product by the product of lengths to strip out magnitude, leaving pure alignment. (E.g., u=(1,2), v=(3,1): 5/(√5·√10) = 1/√2 → 45°.) It's provable via the law of cosines or by rotating u onto the x-axis.

The alignment meter

> 0acutePointing mostly the same way

< 0obtusePointing mostly opposite ways
−1180°Perfectly anti-aligned
For unit vectors, dot product = cos θ exactly — the dot product IS the alignment score when lengths are normalized. Sanity checks: u·u = |u|², perpendicular → 0, v = −u → −|u|².

07Duality & The Transpose

The discovery

A fixed vector u = (2,3) defines a map f(v) = u·v from the plane to the number line — a 1×2 matrix [2 3]. The surprise:

every 2D → 1D linear map is "dot with some vector"

Vectors (arrows) and 1×2 matrices (machines) are the same object wearing two hats. This is a one-to-one, structure-preserving correspondence (an isomorphism) — not a coincidence.

Level lines of f(x,y) = 2x + 3y — the machine's measuring grid
Level lines 2x+3y = c (blue) are perpendicular to u = (2,3) (green) — the "hidden arrow" behind the machine. The map counts lines along u's direction; the lines must cut across it like ruler ticks.

Why (a,b) is perpendicular to the line ax + by = c

Take two points P, Q on the line. Both satisfy ax + by = c. Subtract: a(Pₓ−Qₓ) + b(P_y−Q_y) = 0, i.e. (a,b)·(P−Q) = 0. Since P−Q is a direction along the line, (a,b) is perpendicular to it. The line's coefficients ARE its normal vector.

Your E.4 guess −3x + 2y = 0 was the perpendicular line through the origin — geometrically correct, just one level of abstraction lower than the answer (the vector (2,3)). The line sweeps out u's direction; the vector IS u.

The transpose as translation device

(Mv)·w = v·(Mᵀw)

Transposing a transformation = applying its inverse action to the measuring direction instead of the vector. 2D example: M = 90° rotation, Mᵀ = −90° rotation. Rotating the vector +90° then measuring against w equals measuring against w rotated −90°.

Orthonormal matrices make this concrete: for rotations Q, Qᵀ = Q⁻¹ (rotate back).

09Eigenvalues, Eigenvectors & Change of Basis

Geometric intuition — directions that refuse to tilt

Most directions get tilted by a transformation. But some directions get special treatment: the transformation leaves them on their own line, only scaling them (or flipping sign). Those are the eigenvectors; the scale factor is the eigenvalue λ.

Eigenvectors of [[1.5, 0.5],[0.5, 1.5]] — the diagonal directions never tilt
Before — arrows along (1,1) and (1,−1)
After — (1,1) doubled (λ=2, yellow); (1,−1) untouched (λ=1, green)
Every other direction gets tilted; these two stay on their lines, only scaled. That's the whole idea.
Why they matter: eigenvectors are the directions the transformation "respects" — the lines along which it acts as pure scaling. Everything else is just a mix of those pure behaviors. det = product of eigenvalues (volume = product of stretches along the eigen-directions); trace = sum of eigenvalues. If λ = 0 is an eigenvalue, the transformation squishes along that direction — your det = 0 ⟺ rank-deficient intuition, restated.

Mathematical / computational model

Find them by solving the characteristic equation:

det(A − λI) = 0 → eigenvalues λ; then (A − λI)v = 0 → eigenvectors v
  • Diagonalization: if A has a full set of eigenvectors, A = QΛQ⁻¹ — rotate to the eigenbasis, scale by the λ's, rotate back. Same basis at both ends.
  • The contrast with SVD: eigendecomposition must use the same basis on input and output — and it fails when eigenvectors are missing (the shear [[1,1],[0,1]] has only ONE eigenvector; it can't be diagonalized). SVD allows different input/output bases — that's exactly why it always exists.
  • Symmetry ⟹ orthonormal eigenvectors: symmetric matrices have perpendicular unit eigenvectors — precisely why MᵀM's eigenvectors (V in SVD) are guaranteed perpendicular.

Change of basis — geometric intuition

The vector is real; the coordinates are just a description. A basis is a choice of ruler. Change of basis = re-describing the same point with a different ruler — nothing moves, only the numbers change.

One point, two coordinate systems
Solid axes = standard basis (i, j). Purple = a 45°-rotated basis (v₁, v₂). The dot at grid-address (1,1) is at (√2, 0) in the rotated frame — purely along v₁. Same physical point, different numbers. This is exactly what Vᵀ does in SVD: re-describes a vector in V's frame.

Change of basis — mathematical model

new coords → old coords: x = Bc  ·  old coords → new coords: c = B⁻¹x
  • B = the matrix whose columns are the new basis vectors (written in old coordinates). B·c rebuilds the point from new coordinates; B⁻¹x extracts new coordinates from old.
  • For orthonormal B: B⁻¹ = Bᵀ — the transpose-duality lesson again: rotating into a frame is done by the transpose.
  • Same map, new glasses: a transformation M (old coords) becomes B⁻¹MB in the new coords. Diagonalization A = QΛQ⁻¹ is exactly this: find the basis (Q's columns) where the map becomes diagonal.
  • This is the machinery behind SVD: Vᵀ = change of coordinates into V's frame, then stretch, then U rebuilds in the output frame.

10SVD — The Grand Finale

The one-line definition

M = U Σ Vᵀ

U and V orthonormal (rotations), Σ diagonal non-negative (stretches). Every matrix, no matter how sheary or rectangular, decomposes this way.

M = U Σ Vᵀ — the shear [[1,1],[0,1]] acting on the unit circle

Each click advances one stage of M = UΣVᵀ. Watch the axes: V's stretch axes (purple) rotate into alignment, get stretched by σ = (φ, 1/φ) (yellow), then rotate into U's frame. The final ellipse is exactly what the shear does to the circle in one shot.

The shear resolved (your question)

"Doesn't a shear ruin perpendicularity?" Yes — of the standard basis: (1,0) and (1,1) aren't perpendicular. But SVD never promises that. It promises: there exists a hidden perpendicular pair (V's columns) that gets stretched purely, landing on another perpendicular pair (U's columns). The shear [[1,1],[0,1]] has σ = (φ, 1/φ) ≈ (1.618, 0.618) — the golden ratio! — with stretch axes at 58.3°/−31.7° (input) mapping to 31.7°/−58.3° (output). The images of those special axes are still perpendicular: (1.377,0.851)·(−0.325,0.526) = 0.

One-liner: SVD finds the frame where the map is simple (pure stretch), then translates back. The shear "looks" like a shear only through the standard grid.

How U and V are determined — you only have M

U, S, Vt = np.linalg.svd(M)   # M in → everything out. U, Σ, V are OUTPUTS, forced by M.

The recipe (conceptually):
1. Build MᵀM            ← "M's length fingerprint": |Mx|² = xᵀMᵀMx
2. Eigen-decompose it   ← eigenvectors (sorted) = V's columns; eigenvalues = σ²
3. uᵢ = Mvᵢ / σᵢ        ← push V through M, normalize → U

Demo (M = [[1,1],[0,2]]):  MᵀM = [[1,1],[1,5]] → eigenvalues (0.764, 5.236)
→ σ = (0.874, 2.288) ✓ matches np.linalg.svd output. Mvᵢ = σᵢuᵢ verified numerically.

Why MᵀM? Because it cancels U.

MᵀM = (UΣVᵀ)ᵀ(UΣVᵀ) = VΣ²UᵀUΣVᵀ = VΣ²Vᵀ
  • The output rotation U cancels itself (UᵀU = I) — MᵀM isolates exactly V and σ².
  • MᵀM is symmetric → its eigenvectors are guaranteed perpendicular. That's where SVD's perpendicularity promise comes from — not from M, but from the symmetry of MᵀM.
  • Perpendicular in → perpendicular out: (Mvᵢ)·(Mvⱼ) = vᵢᵀMᵀMvⱼ = σⱼ²(vᵢ·vⱼ) = 0 for i ≠ j.
  • Geometric view: the pullback of the unit circle through M is an ellipse in the input space, equation xᵀMᵀMx = 1. Its axes are V's columns; lengths 1/σ.
"MᵀM is M's confession." It converts any messy rotation+stretch+rotation into a symmetric pure-stretch matrix, and symmetry is what forces perpendicularity. Every piece of SVD's elegance traces back to this one move.

Why Vᵀ and not V? (your confusion, resolved)

OperationWhat it doesExample (V = 45° rotation, x = (1,1))

Vᵀx = (v₁·x, v₂·x) — dotting with each column extracts the coordinate along it (your transpose-duality!). The pipeline: Vᵀ converts standard → V-coordinates, Σ stretches, U converts U-coordinates → standard. The transpose is structurally required, not a notation choice.

U and V: related but independent

  • Both determined by M (never chosen by you) — but computed separately: V from MᵀM (input space), U from MMᵀ (output space).
  • The only bridge: Mvᵢ = σᵢuᵢ (and Mᵀuᵢ = σᵢvᵢ).
  • Symmetric M → U = V (SVD = eigendecomposition). Rectangular M → U is m×m, V is n×n, living in different rooms.

11Key Intuitions Cheat Sheet

Columns are everything

A matrix's columns are where the basis vectors land. Rank, column space, det, SVD all reduce to "what happens to the grid."

Basis

Minimal spanning set; many bases, unique count (dimension); every vector has a unique address.

Column space = range

Span of columns = all reachable outputs. Ax = b solvable ⟺ b in column space.

Rank = surviving dimensions

# independent columns = dimension of output. Rank + nullity = # columns.

det = uniform area scaling

Scales every shape by the same factor; composes multiplicatively; zero ⟺ squished.

Dot product = shadow × scale

|u| × (v's shadow on u). For unit vectors it IS cos θ — the alignment score.

Duality

Every 2D→1D map is "dot with some vector." Level lines are perpendicular to that hidden arrow. Transpose switches hats.

Eigenvectors: lines that don't tilt

Directions the map only scales (λ). det = product of λ's; symmetric ⟹ perpendicular eigenvectors (why MᵀM gives V).

Change of basis = new glasses

Same vector, new coordinates: x = Bc, c = B⁻¹x. A map becomes B⁻¹MB. Vᵀ in SVD is exactly a change of basis.

SVD

M = UΣVᵀ = rotate → stretch → rotate. MᵀM cancels U; symmetry forces perpendicularity. σ's are the stretch report; zero σ = dead dimension.
