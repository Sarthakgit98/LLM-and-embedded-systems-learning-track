micrograd — The Phase 0 Gate

The ~100 lines that use every piece of Phase 0 at once. Forward pass builds a computation graph; backward() walks it in reverse, multiplying local derivatives along every edge — that's the chain rule, as data; one update line steps downhill. Trace one neuron by hand and you understand deep learning's plumbing; everything else is scale and cleverness.

🏁 Phase 0 complete Karpathy Backprop Autodiff Chain Rule interactive

One sentence to carry out

"Every node remembers how it was made; backward() asks each node how much the final loss would wiggle if its inputs wiggled, then multiplies those local answers along the graph." That multiplication is the chain rule; the walking-backwards is backprop.

02The engine — Value, and the ops table

micrograd has one class. A Value holds a number, a list of the Values that made it (_prev), and a function _backward that knows how to push gradients through this one operation:

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):                # local: d/dself = 1, d/dother = 1
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):                # local: d/dself = other, d/dother = self
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def tanh(self):                          # local: d/dt = 1 − t²
        x = self.data
        t = (math.exp(2*x) - 1) / (math.exp(2*x) + 1)
        out = Value(t, (self,), 'tanh')
        def _backward():
            self.grad += (1 - t**2) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        topo = []; visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev: build_topo(child)
                topo.append(v)
        build_topo(self)
        self.grad = 1.0                      # d loss / d loss
        for v in reversed(topo): v._backward()

Every row is just the derivative table from the calculus page, written as a one-liner. The only "learning" in micrograd is multiplying these rows together along the graph.

03Trace one neuron by hand — and see the numbers live

The whole engine in one example (values verified numerically): w = 0.5, x = 2.0, b = 0, target y = 1.

n = w·x + b = 1.0  →  o = tanh(1.0) = 0.76159  →  loss = (y − o)² = 0.05684

Backward, three multiplications — one per edge of the graph:

∂loss/∂o = 2(o−y) = −0.47681  ·  ∂o/∂n = 1−o² = 0.41997  ·  ∂n/∂w = x = 2.0
⇒ ∂loss/∂w = −0.47681 · 0.41997 · 2.0 = −0.40050

The gradient on w is negative, so w += −lr·grad pushes w up — which raises o toward the target. One step at lr = 0.1: w 0.50 → 0.54, loss 0.0568 → 0.0428. Gradient says "which way", lr says "how far".

Manual backprop — slide w, x, b, y, η and watch the chain
Gradient chain: ∂loss/∂o · ∂o/∂n · ∂n/∂w = ∂loss/∂w. The step button applies w ← w − η·∂loss/∂w and shows loss before → after. Watch what happens at extreme w: tanh saturates, ∂o/∂n → 0, and the gradient vanishes — nothing to learn. That's the vanishing-gradient phenomenon, live.

04The deep idea — +=, not = (fan-out)

Every grad in micrograd accumulates. Why? A node can feed many downstream paths, and the total sensitivity of the loss to that node is the sum over every path — the product rule's "two strips" idea, generalized from two to many.

The cleanest case is squaring written as a product: x·x creates two edges into the same node.

x = 3 → out = x·x = 9    backward:  x.grad = 3·1 + 3·1 = 6 = 2x ✓

If micrograd used grad = … instead of grad += …, x*x would return 3 instead of 6, and any weight shared by two paths would silently get half its true gradient. In a real net, shared weights and branching inputs are everywhere (one weight feeds many neurons; the loss is a giant sum) — so the += is not a detail, it is the multi-path chain rule.

05The loss — expectation, MLE, and why "mean" matters

The demo loss is the mean squared error — and that's two things you already know:

  • An expectation (Probability §10): (1/n)·Σ(yᵢ − ŷᵢ)² is the weighted-average machine with each sample weighted 1/n — the "long-run average" face of E[X], taken over the empirical distribution of your data.
  • A likelihood, negated (Probability §08): least squares = maximum likelihood under Gaussian noise. Minimizing MSE is literally maximizing the probability of the data. The LLM connection: cross-entropy loss = −log-likelihood is the same move with a different family (Probability/Info Theory bridge).

Honest caveat — the 1/n is load-bearing, and we have the scar to prove it

Writing the loss as a plain sum Σ(y−ŷ)² (as the classic micrograd demo does) makes the gradient n times bigger. On raw, un-normalized moons data, a fixed lr then diverges — we reproduced it, in the real micrograd library itself: loss 171 → 3×10²⁰⁰ in 5 steps. Two fixes, both visible in the primer:

  • Mean instead of sum — the primer's loss formula was L = E[ℓ] = (1/n)Σ… all along. The 1/n keeps gradient magnitude independent of dataset size.
  • Decaying learning rate — lr = 0.1·0.99steps: big, fast steps early; careful, small ones late. Exactly the primer's "η is how far you trust the linearization" — early on you trust it a lot, later you don't.

(Karpathy's current demo.ipynb sidesteps this entirely with a hinge / max-margin loss, whose gradient is bounded — a different fix for the same instability. All three are legitimate engineering; the math under them is identical.)

06The MLP — dot products, nonlinearity, and why tanh is e

The model is three lines of class definitions over Value:

class Neuron:
    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        act = sum((wi*xi for wi, xi in zip(self.w, x)), self.b)
        return act.tanh() if self.nonlin else act   # neuron = w·x + b, then squash

Three ideas, all Phase 0:

  • Neuron = dot product (Linear Algebra): w·x + b measures x against the weight vector — the same dot-product "measuring" picture. A layer of n neurons is a matrix multiply; each row of the weight matrix is one neuron's w.
  • The nonlinearity is why depth works (Linear Algebra — composition): a stack of affine maps is itself affine. Ten hidden layers without the tanh would compute exactly what one layer computes — no new directions, no expressivity. The tanh is the only thing stopping the whole net from collapsing into a single linear map, and it's precisely the "composition of transformations" lesson applied.
  • tanh is e, differentiated (Calculus §07): tanh = (e²ˣ−1)/(e²ˣ+1). Differentiate it and the exponentials collapse — because "e is its own derivative" — into the one-liner 1 − t². The S-curve's flat ends mean saturated neurons (|t| → 1) pass ~0 gradient; that's the vanishing-gradient trade that motivates ReLU in modern nets.

And the training loop — the whole of the optimization primer, in five lines:

for k in range(150):
    ypred = [model(x) for x in X]                          # forward
    loss  = sum((yi - yout)**2 for yi, yout in zip(Y, ypred)) / len(Y)  # loss (mean!)
    for p in model.parameters(): p.grad = 0.0                    # zero, don't accumulate across steps
    loss.backward()                                               # chain rule
    for p in model.parameters():
        p.data += -lr * p.grad                                    # step downhill (lr decays)

08Honest caveats — what micrograd deliberately doesn't show

  • No minibatching — this is full-batch GD (all data, one exact gradient). SGD = same line on a random subset (Optimization §04); the wobble of real SGD isn't here.
  • No momentum / Adam — one global lr per parameter. Adam's per-parameter step sizes are the upgrade for real nets (Optimization §05).
  • tanh, not ReLU — saturation → vanishing gradients is mild in 2 hidden layers, deadly in 50. That's why modern nets default to ReLU.
  • MSE (or hinge) loss, not cross-entropy — for LLMs the loss is cross-entropy = −log-likelihood of the next token (Info Theory §04–05). Same autodiff machinery, different loss; you'll see it in Phase 2.
  • Scalar autodiff — real frameworks backprop over tensors/matrices (your Linear Algebra is exactly what tensor autodiff is: the same chain rule over higher-rank objects). micrograd is the honest minimal core; everything else is a faster, vectorized version of the same five lines.
  • Init matters — uniform(−1,1) works for this shallow demo; real nets use carefully chosen scales so activations don't saturate at step 0 (the "initialization" design choice from the primer's caveat card).

Gut checks (5 minutes, no notes)

  • a = 4, b = 2, out = a·b. What does the __mul__ backward accumulate into a.grad? Into b.grad? (2·up and 4·up — derivative of a·b w.r.t. each operand is the other operand.)
  • Why is += mandatory, not =? (Fan-out: one node feeds many paths; total sensitivity is the sum over paths — the multi-path chain rule.)
  • In the §03 trace, why does stepping w up reduce the loss? (∂loss/∂w = −0.4 < 0, so w ← w − η·(−0.4) moves w up; o rises toward y.)
  • tanh at n = 5 vs n = 0.5: which passes a bigger gradient, and why does that matter for deep nets? (n=0.5: ∂o/∂n ≈ 0.79; n=5: ≈ 0.0009 — saturated → vanishing gradient.)
  • The loss is (1/n)Σ(y−ŷ)². What breaks if you delete the 1/n? (Gradients n× bigger; the same steps that were fine on 10 points explode on 1000 — the sum-vs-mean divergence we actually hit.)
  • Without the tanh, what would the 2→16→16→1 net compute? (One affine map — composition of linear maps is linear; the whole net collapses. Rank can't grow.)
