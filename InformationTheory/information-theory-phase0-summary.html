Prereq — the one machine you need from Probability

Everything on this page is an expectation — the weighted average machine from Probability section 11: E[g(X)] = Σ g(xᵢ)·p(xᵢ). Information is a function of the outcome (g = −log p); entropy is its expectation. Cross-entropy is an expectation of your model's log-probabilities, weighted by reality's probabilities. 01Intuition — information is surprise, not data size

In everyday language "information" means "stuff in a message." In information theory it means something sharper: how much the message surprised you — how much it reduced your uncertainty. Same word, opposite intuition:

  • "The sun rose this morning." True, but you already knew that. ~0 bits of information — it changed nothing you believed.
  • "It's snowing in Delhi in July." You'd have bet heavily against it. That message is worth a lot — it forces you to tear up your mental model.
  • A 10 GB file of zeros carries ~0 bits if you already knew it was all zeros. Size ≠ information. Information is the reduction in uncertainty, not the byte count.

The surprise ladder — same intuition as probability

EventProbability (your prior)Surprise

A specific 128-bit key is chosen2⁻¹²⁸128 bits

The pattern: the rarer the event, the more information it carries. The lottery number carries ~23 bits — the same information as 23 fair coin flips. Information is a property of an event's probability, not its content or importance.

The honest caveat — meaning is irrelevant

Information theory deliberately ignores what a message says. "Heads" and "tails" carry identical information when equally likely; the sentence "it's raining" carries ~0 bits if you were already staring at rain. Meaning lives in the receiver's model; information lives only in the probability of the event. This feels like a cheat until you see how far pure probability gets you — all of compression, all of LLM training, all of channel coding.

02What information is, exactly — I(x) = −log p(x)

Where the log comes from — counting yes/no questions

Take a fair coin: two equally likely outcomes. To tell someone which happened, you need exactly 1 yes/no question — "heads?" — so the outcome carries 1 bit. Now two fair coins: four equally likely outcomes, and you need 2 questions (first coin? second coin?) — 2 bits. Eight fair possibilities → 3 questions → 3 bits. The pattern:

1 of N equally likely outcomes → log₂ N bits   ·   an event with probability p → I(p) = −log₂ p bits

Each halving of the probability adds exactly one more question — that's what "log" is here: the count of halvings. An event with p = 1/8 sits among 8 equally likely candidates; finding it takes 3 questions; it carries 3 bits. The log is not an aesthetic choice — it's forced by a requirement: information must add for independent events. Knowing the result of two independent coin flips should be twice as informative as one. The only function satisfying I(p·q) = I(p) + I(q) is a logarithm. Base 2 → bits; base e → nats (what ML uses, since derivatives are cleaner).

The halving ladder — rarer event, longer code, more bits
Each halving of the probability adds exactly one bit — the curve I = −log₂ p is just "how many times did we halve?" A fair coin (p=½) costs 1 yes/no question; an event at p=1/16 costs 4. This is also the code-length view: rare events deserve longer binary codes.

Worked examples

  • Fair coin: P(H) = ½ → I(H) = −log₂(½) = 1 bit.
  • Loaded coin, P(H) = 0.9: I(H) = −log₂ 0.9 ≈ 0.15 bits (barely surprising — you expected heads), but I(T) = −log₂ 0.1 ≈ 3.32 bits — the rare tail is worth ~22× more. This asymmetry is the seed of everything in section 03.
  • Two independent coins, HH: p = ¼ → I = 2 bits = I(first) + I(second) — information adds, which is why log is the only choice.
  • 128-bit key: p = 2⁻¹²⁸ → I = 128 bits — "how many yes/no questions you'd need to guess it," which is exactly why 128-bit keys are chosen.

From our discussion — information vs the RV's "weights"

This is the same induced-weight machinery you probed in Probability section 11: the RV assigns each outcome a weight p(x); information is a function of that weight (−log p(x)). The trap is the same one as Jensen: E[−log p(X)] ≠ −log(E[X]). The "average surprise" is not the surprise of the average event — which is exactly why entropy (next) is a number you must compute, not guess.

03Entropy — the expected surprise

Intuition — one number for "how unpredictable is this source?"

Information told you how surprising a single outcome is. But a source (a coin, a die, a language, a next-token distribution) produces many outcomes. Entropy = the average surprise per symbol — the expected information, using the E[g(X)] machine with g = −log p:

H(X) = E[−log p(X)] = −Σ p(xᵢ)·log₂ p(xᵢ)   ·   (natural log → nats)

Three readings of the same number — all correct:

  • Average surprise: how surprised you should be, on average, at each symbol.
  • Average yes/no questions: the minimum bits per symbol you need to transmit the stream (Shannon's source-coding theorem — you can't beat H, and you can reach it).
  • Uncertainty: how hard the next symbol is to predict. For LLMs: entropy of the next-token distribution = "how confused the model is about what comes next."

The illustrative example — a coin you can bend

Fair coin: H = −(½·log₂½ + ½·log₂½) = 1 bit — one question per flip, always needed. Loaded coin (P(H)=0.9): H = −(0.9·log₂0.9 + 0.1·log₂0.1) ≈ 0.469 bits. Less than 1! Because you can do better than asking "heads?" every time — you'd code the common outcome with a short code and the rare one with a long code (0.9·1 + 0.1·3 ≈ 1.2 bits if you must use whole bits, approaching 0.469 with fractional codes). The more lopsided the coin, the lower the entropy; a certain event has H = 0 — zero questions needed, zero surprise, zero information. Entropy is maximized when all outcomes are equally likely (uniform): that's when you're maximally uncertain.

Gut checks

  • Fair 6-sided die: H = log₂ 6 ≈ 2.585 — confirm it's less than 3 (the 8-sided die). Fewer outcomes, less uncertainty.
  • Two independent fair coins (one source, 4 outcomes): H = 2 bits = 1 + 1 — entropy adds for independent sources, exactly like information.
  • Why is H(0.9/0.1) ≈ 0.47 < 1? Because surprise is a nonlinear function (log): the 0.9-probability event is only slightly less than certain, and it dominates the average.

04Cross entropy — your model vs reality

Intuition — you built your code for a world that isn't quite this one

Entropy is a property of one distribution. But machine learning lives in a two-distribution world: p = reality (the true distribution your data comes from) and q = your model (what you believe, what your neural net outputs). You built your code / your probabilities with q in mind — but reality keeps drawing from p. Cross entropy = how many bits you actually pay per symbol, on average, when your beliefs q meet reality p.

H(p, q) = −Σ p(x)·log₂ q(x)   =   H(p) + KL(p ‖ q)   ·   KL = Σ p(x)·log₂ p(x)/q(x)

Read the formula with the expectation machine: H(p,q) = E_p[−log q(X)] — an expectation of your model's log-probabilities, weighted by reality's probabilities. It splits into two parts:

  • H(p) — the unavoidable cost: even a perfect model pays the entropy of reality.
  • KL(p‖q) — the extra bits you pay because q isn't p. The penalty for wrong beliefs. KL ≥ 0 always (Gibbs' inequality), and KL = 0 exactly when q = p. So H(p,q) ≥ H(p) — cross entropy can never beat reality's own entropy; a mismatched model only ever adds cost.

Worked example — the fair coin, mis-modeled

Reality: fair coin, p = (½, ½). Your model (wrongly) believes q = (0.9, 0.1). Your code spends −log₂ q bits on each outcome, but reality produces them with p's probabilities:

H(p,q) = −(½·log₂0.9 + ½·log₂0.1) = −(½·(−0.152) + ½·(−3.322)) = 1.737 bits  ·  H(p) = 1  ·  KL = 0.737

You pay 1.737 bits per symbol where a perfect model pays 1 — the extra 0.737 bits are the tax on being wrong. Notice the penalty is asymmetric: if you flip it (reality 0.9/0.1, model fair), H(q,p) = 1.000 — different price! Cross entropy is not symmetric, because the penalty explodes when your model assigns ~0 probability to something reality actually produces (log₂ 0.1 = −3.32), while overestimating the common event is cheap (log₂ 0.9 = −0.15). Being overconfident about rare events is the expensive sin.

Why LLMs train on this — the bridge to section 05

Next-token prediction: reality p is the true distribution of the next token given the context; the model outputs q. Training = minimizing the average −log q(token) over real data — i.e., minimizing cross entropy (equivalently maximizing log-likelihood; recall Probability section 08: cross-entropy loss = negative log-likelihood). The minimum is achieved exactly when q = p — so training is literally "make your model's beliefs match reality," and the best you can ever do is pay reality's own entropy H(p). Section 05 makes this relationship visible.

05Cross entropy illustrated — how one context relates to another

Two sources, one slider each — watch the penalty appear and vanish

Here's the whole story in one interactive: p = reality (true bias of a coin) and q = your model's belief (the bias you assume). The left panel shows both distributions; the right panel shows the three entropies — H(p) (reality's floor), H(q) (your model's self-confidence, irrelevant to the cost), and H(p,q) (the stacked bar: floor + penalty). The amber penalty is KL: it's zero when q = p, and grows the more your model disagrees with reality.

The relationship: H(p,q) = H(p) + KL(p‖q) — reality's entropy plus the price of your model
Set q = p and the amber penalty vanishes: H(p,q) = H(p), the floor. Move q away and the penalty grows — fast when q gets overconfident about an outcome reality actually produces (rare-event overconfidence is the expensive sin). The green-outlined bar is always H(p) + KL = H(p,q), never below the blue floor. Perplexity = 2^H(p,q): "the effective number of equally-likely choices the model is confused between."

Entropy of one context vs another — the three relationships to keep

  • H(p,q) ≥ H(p): cross entropy can never beat the true entropy — the best model pays exactly the floor, a wrong model pays more. This is the "no free lunch" of compression and of prediction.
  • H(p,q) = H(q,p) only when p = q: cross entropy is asymmetric (KL is asymmetric). Believing q when reality is p costs a different amount than the reverse — the price of overconfidence about rare events isn't refunded.
  • H(q) is a distraction: a model's own entropy measures how confident it feels, not how right it is. A confidently wrong model can have tiny H(q) and huge H(p,q). (This is why a model's "I'm 99% sure" means nothing without calibration against reality.)

Gut checks (do these against the demo, then by hand)

  • Set q = p = 0.5: KL = 0, H(p,q) = 1.000 = H(p) ✓.
  • Set q = p = 0.9: H(p,q) = H(p) = 0.469 — a wrong-looking model can still be perfect if it matches reality. The cost is about mismatch, not about q being "fair."
  • p = 0.5, q = 0.05: your model is sure the fair coin is heavily loaded — H(p,q) = −(0.5·log₂0.05 + 0.5·log₂0.95) ≈ 2.17 bits, KL ≈ 1.17. The rare-event overconfidence tax, visible.
  • By hand: H(0.9, 0.1) = 0.469 bits and perplexity = 2^0.469 ≈ 1.38 — "the model is confused between ~1.4 equally likely outcomes" (mostly it knows).

06The LLM payoff — perplexity, and why training is cross-entropy

Putting it together for a next-token predictor

  • Training: the model outputs q(token | context). The loss averaged over real data is the empirical cross entropy −(1/N)Σ log q(yᵢ) — an expectation over reality p of −log q. Minimizing it pushes q → p (section 05's demo: penalty → 0). This is exactly the "cross-entropy = negative log-likelihood = LLM training objective" bridge from Probability section 08.
  • Evaluation: perplexity = 2^H(p,q) — the effective number of equally-likely next tokens the model is confused between. Perplexity 20 ≈ "as confused as a fair 20-sided die"; perplexity 1 = perfectly confident and right. Lower perplexity = better model (on that data).
  • Why log base matters: bits vs nats is a constant factor (log₂ x = ln x / ln 2). ML libraries report nats (natural log) because derivatives of ln are cleaner; perplexity conventionally uses base 2. Don't let the unit switch scare you — it's a rescaling, not a different concept.

From our discussion — the honest summary

Information is surprise, measured in yes/no questions (log). Entropy is the average surprise of a source — how unpredictable it is. Cross entropy is what you actually pay when your beliefs (q) meet reality (p): the floor H(p) plus the KL penalty for mismatch. The penalty is ≥ 0, asymmetric, and explodes for rare events your model writes off. LLMs are trained by minimizing exactly this, and perplexity reports it on a familiar scale. Everything here is one expectation — the E[g(X)] machine from Probability section 11, with g = −log q and weights p.
